# Coffee CLI 启动页设计

## 目标

将目前单行的 `Coffee CLI 已启动` 替换为更有品牌感的静态启动页。启动页以大号空心斜体 `COFFEE` 为第一视觉层，在下方并排展示冰美式和热拿铁，最后保留一行启动状态与操作提示。

本次只调整成功启动后的终端展示，不改变 Agent、命令、设置、模型或工具行为。

两杯咖啡的顶部、杯身、杯底和名称分别位于同一行。底部只保留一行：`Coffee Agent is ready    / 查看命令 · Ctrl+C 退出`。

## 颜色

- `COFFEE`：亮青色。
- 副标题：灰色。
- 冰美式：亮蓝色。
- 热拿铁：暖黄色。
- 启动状态：紫色；操作提示：灰色。

设置 `NO_COLOR` 时保留完整字符画和布局，只移除 ANSI 颜色。启动页是静态内容，不增加动画、延迟或光标控制。

## 终端适配

新增一个独立的启动页渲染模块，根据终端能力返回字符串：

- TTY 且列宽能够容纳最长一行时，显示完整启动页。
- 窄终端或非 TTY 环境显示紧凑文本：`Coffee CLI 已启动，输入 /exit 或按 Ctrl+C 退出。`
- 宽度判断使用去除 ANSI 控制码后的可见字符宽度，避免字符画自动换行错位。

紧凑回退保留现有输出，也让自动化管道和测试日志保持易读。

## 代码结构

新增 `src/startup-banner.ts`，负责：

- 保存 Logo 与双咖啡字符画常量。
- 计算完整启动页所需列宽。
- 根据 `isTTY`、`columns` 和 `useColor` 渲染完整或紧凑版本。
- 仅在启用颜色时插入 ANSI 颜色码。

`src/cli.ts` 只在 Agent 配置成功后调用启动页渲染函数并写入输出。现有 `terminal-format.ts`、活动动画和 `/like` 设置不承担启动页布局职责，也不需要重构。

## 异常与边界

- API Key 缺失或 Agent 创建失败时，保持当前错误流程，不打印成功启动页。
- `stdout.columns` 缺失、不是有限正数或小于完整启动页宽度时，使用紧凑回退。
- 启动页不读取 `coffee.settings.json` 中的动画偏好；冰美式和热拿铁作为品牌角色始终同时展示。
- 不增加运行时依赖。

## 验证

新增纯函数测试覆盖：

- 宽 TTY 输出空心斜体 `COFFEE`、两杯咖啡和操作提示。
- 两杯咖啡的杯底和名称处于对应的同一行。
- `NO_COLOR` 输出不含 ANSI，但保留完整字符画。
- 窄终端、非 TTY 和缺失列宽时回退到紧凑启动文案。
- 彩色宽 TTY 输出包含不同的 Logo、冰美式和热拿铁颜色。

更新 CLI 子进程测试，确认紧凑启动文案仍存在。最后运行 `npm test` 和 `npm run check`。
