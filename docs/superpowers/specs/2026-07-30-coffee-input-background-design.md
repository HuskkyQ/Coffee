# Coffee 输入框背景设计

## 目标

调整主聊天输入框的视觉层级：

- 上下两条 `─` 边框使用终端默认前景和背景，不再应用主题颜色。
- 中间输入行使用当前主题的 `inputBackground`，背景延伸到终端行尾。
- 输入文字继续使用主题的 `primary`，主题切换后下一次输入立即换色。
- 空输入与有文字时保持相同的一行输入高度。

显式确认范围为整条中间输入行，不是只给已输入文字着色。

## 非目标

- 不修改命令下拉、通用选择器、模型输出或工具状态的配色。
- 不增加新主题或新设置项。
- 不改变输入框边框字符、输入行为、光标位置或提交逻辑。

## 渲染设计

主输入提示仍由三行组成：

```text
────────────────────────
输入内容
────────────────────────
```

上下边框直接输出原始 `─` 字符，不调用主题绘制函数。

在支持颜色的交互终端中，中间行先启用 `primary` 前景色和
`inputBackground` 背景色，输出输入内容，然后在复位样式前使用 ANSI
Erase in Line 填充到行尾。该控制序列不增加显示宽度，因此不会像用空格
补齐整行那样触发终端自动换行，也不会使 Inquirer 重新出现空输入双行。

空输入继续使用零宽锚点，使原始提示行的 JavaScript 长度非零，同时保持
显示宽度为零。光标仍停留在真实输入内容之后。

在 `NO_COLOR`、非 TTY 或颜色能力为 `none` 时，不输出背景色或 Erase in
Line 控制序列，继续使用现有纯文本渲染。

## 代码边界

- `src/theme.ts`：为主题绘制函数增加可选的“用当前背景填充到行尾”能力，
  仅在颜色模式开启时生效。
- `src/chat-input.ts`：边框改为原始文本；中间输入行启用背景和行尾填充。
- `test/theme.test.ts`：验证行尾填充控制序列位于样式复位之前，纯文本模式
  不产生控制序列。
- `test/chat-input.test.ts`：验证边框无样式、输入背景覆盖整行、三种主题和
  零宽空输入行为。

## 验收

1. 三种主题下，上下边框都不含 ANSI 前景色或背景色。
2. 中间输入行使用对应主题背景，并填充到终端行尾。
3. 空输入和有文字输入均保持一行高度，光标位于文字末尾。
4. `/theme` 切换后下一次主输入使用新背景。
5. `NO_COLOR` 和非 TTY 输出不含新增 ANSI 控制序列。
6. 输入框聚焦测试、完整测试套件和 TypeScript 检查全部通过。
