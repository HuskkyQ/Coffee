# Coffee Shell 与测试执行能力设计

## 目标

让 Coffee 能在启动时识别出的当前工作区内执行终端命令，从而形成“读取代码、修改代码、运行测试、分析失败、继续修复、再次验证”的闭环。

本次只实现 Shell 与测试执行能力。结构化任务规划和 RAG 分别使用后续独立的设计、计划和实现周期。

## 已确认的产品边界

- 只提供一个模型中立的 `shell` 工具，测试命令也是 Shell 命令。
- 不允许模型指定工作目录；命令始终以启动时的 `workspaceRoot` 为工作目录。
- 严格匹配的读取、搜索、测试和类型检查命令可以自动执行。
- 修改文件、安装依赖、Git 写操作、长期运行或无法识别的命令必须逐次确认。
- 系统级高危命令直接禁止，不提供授权入口。
- 确认只对当前完整命令生效，Coffee 不记住授权。
- 设计与任何模型厂商解耦，DeepSeek 和后续厂商共用同一工具定义与结果协议。
- 这是 Coffee 自身的权限策略，不是操作系统级沙箱。

## 非目标

- 不实现容器、虚拟机、macOS sandbox 或其他操作系统级隔离。
- 不允许模型选择任意 `cwd`，也不实现跨工作区执行。
- 不增加独立的 `test`、`python` 或长期后台任务工具。
- 不实现全屏 TUI、可展开日志面板或持久化完整命令日志。
- 不实现永久允许、按命令记忆授权或全局 Shell 权限配置。
- 不保证经过用户确认的任意复杂 Shell 命令无法绕过路径启发式检查。

## 方案选择

采用单一 `shell` 工具和集中式风险策略。

没有采用独立 `test` 工具，因为测试最终仍由项目脚本执行，拆分工具会重复执行、超时、输出和取消逻辑，也不会使 `npm test` 本身更安全。

没有采用纯固定命令白名单，因为它不能覆盖真实项目中的诊断、构建和修复命令。Coffee 使用“严格自动执行列表、默认确认、高危禁止”的三级策略：只有可以明确证明符合自动规则的简单命令自动执行，所有未知命令默认确认。

## 工具协议

`shell` 接收以下参数：

```json
{
  "command": "npm test",
  "timeout": 60
}
```

- `command` 必填，必须是去除首尾空白后仍非空的字符串。
- `command` 最大 4096 个字符。
- `timeout` 可选，单位为秒；默认 60 秒，必须是有限正数，最大 300 秒。
- 不接受 `cwd`、`env`、Shell 路径或后台执行参数。
- 输入对象不允许额外字段。

工具返回稳定的结构化结果：

```json
{
  "ok": false,
  "command": "npm test",
  "exitCode": 1,
  "durationMs": 2384,
  "timedOut": false,
  "cancelled": false,
  "truncated": false,
  "output": "具体测试错误"
}
```

- 退出码为 `0` 时 `ok` 为 `true`。
- 非零退出码是正常执行结果，不作为注册表异常抛出。
- 未启动进程的失败返回 `code` 和中文 `error`。
- `exitCode` 在进程未能启动、超时终止或用户取消时为 `null`。
- `output` 合并 stdout 与 stderr，并保持 Coffee 实际收到数据块的顺序。

稳定错误代码：

- `INVALID_ARGUMENT`
- `COMMAND_DENIED`
- `USER_REJECTED`
- `SPAWN_FAILED`
- `TIMED_OUT`
- `CANCELLED`

## 组件职责

### `ShellCommandPolicy`

负责参数校验和命令风险分类，不启动进程。返回：

```ts
type ShellDecision =
  | { kind: "auto"; reason: string }
  | { kind: "confirm"; reason: string }
  | { kind: "deny"; reason: string };
```

分类优先级固定为：

1. 输入是否合法；
2. 是否命中禁止规则；
3. 是否含复杂 Shell 语法；
4. 是否严格匹配自动执行规则；
5. 其他情况默认确认。

策略只把 ASCII 命令名和经过白名单校验的选项识别为自动命令。它不尝试实现完整 Shell 解析器；无法可靠识别时必须降级为确认。

### `ShellExecutor`

只负责已获准命令的执行：

- 以固定 `workspaceRoot` 为 `cwd`。
- 使用 Bash 的非登录模式执行完整命令。Unix 优先使用 `/bin/bash`，不可用时在 `PATH` 中查找 `bash`；找不到可用 Bash 时返回 `SPAWN_FAILED`，不静默切换成语义不同的 Shell。
- 启动独立进程组，以便超时或取消时终止整个进程树。
- 合并、清理并增量发送 stdout 与 stderr。
- 返回退出码、耗时、取消、超时和截断信息。
- 清理定时器、监听器和进程跟踪状态。

进程执行借鉴 Pi 的成熟行为：支持增量输出、进程树终止、超时、取消、ANSI 清理和上下文截断。Coffee 不依赖 Pi 的内部包，也不复制 Pi 的 TUI 或临时完整日志功能。

### `ToolInteraction`

扩展现有本地交互边界，负责：

- 暂停工具动画；
- 显示完整命令和分类原因；
- 使用 `[y/N]` 进行单次确认；
- 增量写出清理后的命令输出；
- 在完成、拒绝或取消后恢复输入与终端状态。

Shell 工具通过注入的交互回调显示本地输出。模型供应商适配器和工具注册表仍只处理最终 JSON 结果，不感知 CLI 实现。

## 风险分类

### 自动执行

自动执行必须同时满足：

- 命令不含管道、重定向、串联、命令替换或换行；
- 命令名精确匹配；
- 选项属于对应命令的安全子集；
- 所有显式路径都位于工作区内；
- 没有出现禁止参数或可启动外部程序的参数。

第一版自动命令族：

- `pwd`
- 受限参数的 `ls`
- 受限参数的 `rg`；禁止 `--pre` 等可启动外部程序的选项
- `git status`
- 受限参数的 `git diff`
- 受限参数的 `git log`
- 受限参数的 `git show`
- `npm test`
- `npm run test` 及 `npm run test:*`
- `npm run check`
- `npx --no-install tsc --noEmit`

自动 Git 命令禁用分页器和外部 diff。自动命令的具体选项白名单在实现中以独立常量和单元测试固定，不能通过“未知选项仍放行”的方式扩展。

`npm test` 与 `npm run ...` 会执行项目定义的脚本，理论上可以执行任意操作。它们自动执行的前提是当前工作区可信；Coffee 必须在工具说明和文档中明确这一点。

### 需要单次确认

以下命令默认需要确认：

- `npm install`、`pnpm add` 等依赖变更；
- `npm run build`、`npm run dev` 和其他项目脚本；
- `rm`、`mv`、`cp`、`mkdir` 等文件变更；
- `git add`、`git commit`、`git push` 等 Git 写操作；
- 含复杂 Shell 语法但未命中禁止规则的命令；
- 所有无法被自动规则明确识别的命令。

复杂语法至少包括：

- `|`、`>`、`<`、`&&`、`||`、`;`；
- 反引号命令替换和 `$()`；
- 命令中的换行；
- 其他会改变简单单命令语义的 Shell 操作符。

确认界面必须显示规范化后的完整命令和中文原因：

```text
Coffee 准备执行命令

$ npm install

原因：安装或修改项目依赖
仅允许本次执行？ [y/N]
```

只有去除空白并转为小写后等于 `y` 的输入才同意。空输入、其他输入、非交互环境或确认期间的取消都拒绝执行。

### 直接禁止

系统级高危命令不提供确认入口，包括：

- `sudo`、`doas`；
- 关机、重启和电源控制；
- 格式化磁盘、修改分区和擦除磁盘；
- 删除系统根目录、用户主目录或整个工作区；
- `curl ... | sh`、`wget ... | bash` 等下载后直接执行；
- 能被策略明确识别出的工作区外路径访问。

禁止规则不是操作系统沙箱。经过确认的任意 Shell 可以使用间接表达式或子程序产生策略无法静态证明的行为；CLI 必须明确显示完整命令，让用户保留最后决定权。

## 执行环境

子进程不直接继承 `process.env`。Coffee 构造最小环境，保留命令执行所需的基础变量，例如：

- `PATH`
- `HOME`
- `TMPDIR`、`TMP`、`TEMP`
- `LANG`、`LC_ALL`、`LC_CTYPE`
- `TERM`、`COLORTERM`、`NO_COLOR`

并固定：

- `CI=1`
- `PAGER=cat`
- `GIT_PAGER=cat`
- 禁用 Git 外部 diff 的相关环境变量

DeepSeek、Tavily、其他模型厂商凭据、Coffee 内存中的鉴权信息以及名称明显为 API key、token 或 secret 的环境变量不得传给子进程。这里保证的是“不继承凭据环境变量”，不是文件系统隔离；Shell 仍在用户权限下运行。

## 输出、截断与终端显示

- 使用 `TextDecoder` 的流式模式，保证跨数据块 UTF-8 字符不损坏。
- 移除 ANSI 控制序列、回车重绘控制和不可安全展示的二进制内容。
- stdout 与 stderr 以数据块到达 Coffee 的顺序合并。
- CLI 以追加方式实时显示清理后的输出，不使用向上移动光标或整帧重绘。
- 审批和输出开始前暂停咖啡动画，避免动画与命令日志交错。
- 终端最多追加 2000 行或 200KB；达到任一上限后停止继续刷屏，并显示一次截断提示。
- 传给模型的输出最多 2000 行或 50KB。先按行保留前 1000 行和后 1000 行，再按 UTF-8 字节边界保留前 25KB 和后 25KB；截断标记额外注明省略的行数或字节数。
- 第一版不把完整输出写入临时文件，避免新增秘密落盘和清理生命周期。

## 取消、超时与进程生命周期

- 默认超时 60 秒，最大 300 秒。
- 工具收到已取消的 `AbortSignal` 时不得启动进程。
- 执行期间取消或超时必须终止整个进程组，而不只终止直接子进程。
- `Ctrl+C` 沿用 Coffee 现有退出语义：先终止当前命令及其进程树、固定已经显示的安全输出并恢复终端状态，然后由 CLI 的统一中止流程正常退出。Shell 组件不得自行抛出未处理异常。
- 取消、超时、spawn 失败和正常非零退出必须产生不同的结构化结果。
- 工具结束后不得残留定时器、输出监听器或子进程跟踪记录。

## 非交互行为

- 严格匹配的自动命令可以执行。
- `confirm` 命令直接返回 `USER_REJECTED`，不得等待输入。
- `deny` 命令照常返回 `COMMAND_DENIED`。
- 非交互模式不降低任何风险等级。

## Agent 数据流

```text
模型调用 shell
    ↓
校验 command 与 timeout
    ↓
ShellCommandPolicy 分类
    ├─ deny    → 返回 COMMAND_DENIED
    ├─ confirm → ToolInteraction 单次询问
    │              ├─ 拒绝 → 返回 USER_REJECTED
    │              └─ 同意 → 执行
    └─ auto    → 直接执行
                       ↓
              ShellExecutor 启动进程
                       ↓
             CLI 增量显示安全输出
                       ↓
         返回退出码、耗时、状态和截断输出
                       ↓
       模型决定继续修复、再次测试或结束
```

用户拒绝、命令被禁止或执行失败都必须作为工具结果进入模型上下文。模型不能把未执行的命令描述成已经成功运行。

## 测试设计

### 策略单元测试

- 自动、确认和禁止命令分类正确。
- 复杂 Shell 语法不被自动放行。
- 工作区外路径和系统级高危命令被阻止。
- 命令长度、空命令、额外字段和超时参数得到校验。
- 前导空白、引号、选项和值的常见变体不能绕过规则。
- `rg` 可执行外部程序的选项不能自动执行。
- 未知命令和未知选项默认确认。

### 执行器测试

- 命令始终以 `workspaceRoot` 为 cwd。
- 凭据环境变量不进入子进程。
- stdout、stderr、分块 UTF-8 和控制字符得到正确处理。
- 非零退出码作为普通失败结果返回。
- spawn 失败、超时和取消产生不同结果。
- 超时与取消终止整个进程树。
- 长输出按头尾规则截断且截断标记准确。
- 完成后没有残留监听器、定时器或进程。

### CLI 交互测试

- 自动命令不询问。
- 风险命令显示完整命令和原因。
- 只有 `y` 执行一次，拒绝后没有 spawn。
- 非交互环境和确认期间取消不会误执行。
- 审批时动画暂停，结束后输入与终端状态恢复。
- 增量日志只追加一次，不重复显示历史输出。
- `Ctrl+C` 不产生未处理的 readline 或子进程异常。

### Agent 集成测试

- 模型可以通过现有注册表调用 `shell`。
- 最终结果进入下一轮模型上下文。
- 测试失败后模型可以继续读取、修改和再次测试。
- `USER_REJECTED` 与 `COMMAND_DENIED` 明确回传模型。
- 用户中断后不启动新的工具或后续模型轮次。

### 全量回归

- Shell 新增测试全部通过。
- Coffee 现有测试全部通过。
- `npm run check` 通过。

## 验收标准

以下场景必须成立：

1. 用户要求修复 TypeScript 错误并运行测试时，Coffee 可以修改代码、自动执行 `npm test`、读取失败并继续修复。
2. `npm test` 在严格匹配规则下无需确认；`npm install` 必须逐次确认。
3. `sudo` 和系统级破坏命令不会启动进程。
4. `Ctrl+C` 能终止当前命令及其子进程，Coffee 不出现未处理异常。
5. DeepSeek、Tavily 和其他凭据环境变量不会进入子进程。
6. 长输出不会淹没模型上下文或无限刷屏，且不会重复显示。
7. 工具定义、执行和结果协议不依赖具体模型厂商。
