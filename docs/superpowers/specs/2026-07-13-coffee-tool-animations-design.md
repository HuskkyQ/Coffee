# Coffee Tool Animations 设计

## 目标

把生硬的 `Tool>` 日志替换成多行咖啡动画，并增加 `/like` 命令，让用户为所有工具统一选择冰美式或热拿铁。动画和设置只影响终端展示，不改变 DeepSeek、Tavily、IPWho 或工具参数。

## 动画样式

冰美式使用透明高杯、吸管、冰块和深色咖啡。动画通过吸管轻微摆动、冰块位置交替和咖啡表面变化形成循环，主色为青色和亮蓝色。

```text
        ╲
         ╲
     ╭───╲──╮
     │ ◇  ◆ │
     │  ◆ ◇ │
     │██████│
     ╰──────╯
  冰美式正在翻找网页…
```

热拿铁使用陶瓷杯、杯柄、蒸汽和心形拉花。动画通过蒸汽位置变化以及 `♡`、`♥` 交替形成循环，主色为暖黄和奶咖色。

```text
       (  )
        )(
     ╭──────╮
     │  ♡   │╮
     │      ││
     ╰──────╯╯

  拿铁正在感知你的位置…
```

用户选择的样式是全局偏好：搜索、定位和未来新增的工具都使用同一种咖啡造型。工具类型只决定底部文案以及完成或失败文案。未设置偏好时默认使用冰美式。

## `/like` 命令

输入 `/like` 后显示交互菜单：

```text
选择你喜欢的工具动画：

  1. 冰美式
  2. 热拿铁

当前选择：冰美式
请输入 1 或 2：
```

菜单中的 `1` 选择 `americano`，`2` 选择 `latte`。同时支持快捷命令：

```text
/like americano
/like latte
```

`/like` 及菜单输入不会发送给 DeepSeek。无效参数或菜单输入会显示 `/like`、`/like americano`、`/like latte` 的正确用法，不修改当前设置。保存成功后立即影响下一次工具调用。

## 实时命令下拉

TTY 使用基于 `@inquirer/core` 的自定义输入 Prompt。用户输入 `/` 时立即在输入行下方显示已注册命令，继续输入时按命令名称实时过滤；`NO_COLOR` 只关闭颜色，不关闭下拉交互：

```text
You> /

  › /like    选择咖啡动画
    /exit    退出 Coffee
```

`↑`、`↓` 切换高亮项；`Tab` 把高亮命令填入输入行，其中 `/like` 补全为 `/like ` 以便继续输入参数；`Enter` 执行高亮命令；`Esc` 收起当前下拉列表但保留输入。普通聊天文本继续支持中文输入和常规编辑。非 TTY 环境保留普通逐行输入，不绘制下拉列表。

命令由一个注册表统一定义名称、说明以及是否接受参数。初始注册表只有 `/like` 与 `/exit`，下拉列表、模糊纠错和命令路由都读取同一个注册表。

## 未知命令阻断与纠错

所有以 `/` 开头的输入先在本地解析，未知命令永远不会发送给 DeepSeek。命令名称与注册表进行前缀和编辑距离匹配；前缀相关或编辑距离不超过 2 时，询问是否使用最相近命令：

```text
未找到命令：/likes
是否改用 /like？ (Y/n)
```

Enter 或 `Y` 接受建议，`N` 或 Esc 取消。纠正命令名称时保留后面的参数，例如 `/likes latte` 建议为 `/like latte`。没有符合阈值的建议时，显示未知命令错误以及完整可用命令列表，然后返回输入提示。`/likes`、`/lik` 和 `/liek` 都应建议 `/like`。

## 设置文件

偏好保存在项目根目录的 `coffee.settings.json`：

```json
{
  "coffee-preferences": {
    "animation": "latte"
  }
}
```

`coffee-preferences.animation` 只允许 `americano` 或 `latte`。文件或该字段不存在时使用默认值 `americano`；字段值无效时警告并使用默认值。保存时重新读取设置、只更新 `coffee-preferences.animation`，并保留其他顶层设置以及 `coffee-preferences` 中的其他字段。文件不存在时自动创建，JSON 使用两个空格缩进并以换行结尾。

如果整个设置文件不是合法 JSON，启动时警告并使用默认值；为避免破坏未来的其他设置，`/like` 拒绝覆盖损坏的文件，并提示用户修复或删除该文件。

## 工具生命周期与输出

Agent 在每个工具开始、成功或失败时发送活动事件。CLI 同一时间只渲染当前正在执行的工具；模型一次返回多个工具时，按照现有顺序逐个展示。

动画以固定高度在终端原地刷新，不向下堆叠内容。开始时隐藏光标，每 140 毫秒切换一帧；结束时停止计时器、清除整个动画区域并恢复光标。成功后只保留一行：

```text
✓ 网络信息已经带回 · 1.3s
✓ 大致位置已经确认 · 0.8s
```

失败时同样清除动画，并保留红色状态：

```text
✗ 联网搜索暂时失败 · 1.3s
✗ 近似定位暂时失败 · 0.8s
```

耗时从工具开始计算到工具执行器返回，不包含 DeepSeek 根据工具结果生成最终回答的时间。

## 终端兼容

只有彩色 TTY 播放多行动画。非 TTY 或设置 `NO_COLOR` 时，不发送光标移动指令，而是打印一条开始提示和一条完成提示。所有成功、失败和异常路径都必须停止计时器并恢复光标，避免终端残留隐藏光标或持续运行的动画。Ctrl+C 在普通输入、命令下拉和纠错确认期间沿用现有的干净退出行为。

## 代码边界

新增活动指示器模块，负责帧、颜色、计时、光标移动和降级输出；新增设置模块，负责读取、校验和保存 `coffee.settings.json`；新增输入模块，使用 `@inquirer/core` 管理 TTY 输入、下拉列表与按键，并为非 TTY 提供普通行输入；新增命令注册表与纯函数纠错模块。`agent.ts` 只发送工具生命周期事件；`cli.ts` 只协调输入、命令、设置、Agent 和活动指示器。现有 Markdown 渲染、角色提示词、API 配置和工具参数保持不变。`@inquirer/core` 是唯一新增的运行时依赖，不引入 React 或完整 TUI 框架。

## 验证

测试覆盖冰美式与拿铁帧、TTY 光标控制、非 TTY 降级输出、成功与失败文案、耗时格式、Agent 生命周期事件、`/like` 两种交互方式、默认偏好、持久化、保留其他设置、无效值和损坏 JSON，以及命令过滤、上下选择、Tab 补全、未知命令阻断、相近建议、参数保留、确认与取消。子进程测试禁用真实网络，以证明任何未知 `/...` 都不会发出 API 请求。最后运行完整 `npm test` 和 `npm run check`。
