# Coffee 安全代码工具设计

## 目标

让 Coffee 在启动时识别出的工作区内读取、搜索、创建和精确修改文本代码，同时保留用户对每次文件变更的最终控制权。

本次实现的工具名称与 Pi 的核心代码工具对齐：

- `ls`
- `find`
- `grep`
- `read`
- `edit`
- `write`

Coffee 额外提供 `set_env`，用于在本地安全地设置 `.env*` 文件中的变量值。

所有工具继续通过现有模型中立的工具注册表暴露给模型，不与 DeepSeek、OpenAI 兼容接口或任何特定厂商耦合。

## 非目标

- 不提供 `bash`、通用 Shell、任意进程执行或 Python 解释器。
- 不提供删除、重命名、移动文件或目录的工具。
- 不允许 `write` 覆盖已有文件；已有文件只能通过 `edit` 精确修改。
- 不自动运行测试、格式化器、构建命令或 Git 命令。
- 不实现全屏 TUI；Diff 使用当前 CLI 内的行内交互。
- 不把路径校验描述为操作系统级沙箱。它只能约束 Coffee 自身的文件工具。

## 与 Pi 的对齐边界

Coffee 沿用 Pi 易于模型理解的工具命名和编辑协议：

```json
{
  "path": "src/example.ts",
  "edits": [
    {
      "oldText": "const value = 1;",
      "newText": "const value = 2;"
    }
  ]
}
```

每个 `oldText` 都必须在原始文件中精确且唯一地出现一次；同一调用中的所有替换都基于同一份原始内容计算，不能相互重叠或嵌套。`newText` 可以为空，用于删除文件内部的代码，但不能删除整个文件。

Coffee 有意不对齐 Pi 的以下能力：

- Pi 核心工具允许更宽松的绝对路径解析；Coffee 强制限制在当前工作区。
- Pi 提供 `bash`；Coffee 第一版不提供任意命令执行。
- Pi 的核心 `edit`/`write` 可以直接落盘；Coffee 每次变更都必须经过本地 Diff 确认。
- Pi 的 `write` 可以覆盖文件；Coffee 的 `write` 只创建新文件。

## 工具协议

### `ls`

列出目录中的直接子项。

```json
{
  "path": "src",
  "limit": 200
}
```

- `path` 可选，默认为工作区根目录。
- `limit` 可选，默认及最大值为 500。
- 返回相对工作区的 POSIX 风格路径，并标记目录。
- 默认隐藏永久禁止路径和受保护路径。

### `find`

按 glob 查找文件名。

```json
{
  "pattern": "src/**/*.test.ts",
  "path": ".",
  "limit": 200
}
```

- `pattern` 必填。
- `path` 可选，默认为工作区根目录。
- `limit` 可选，默认及最大值为 1000。
- 只返回文件，不返回受保护或永久禁止路径。

### `grep`

搜索文本内容。

```json
{
  "pattern": "createConversation",
  "path": "src",
  "glob": "*.ts",
  "ignoreCase": false,
  "literal": true,
  "context": 2,
  "limit": 100
}
```

- `pattern` 必填，可作为正则表达式；`literal: true` 时按普通字符串搜索。
- `path`、`glob`、`ignoreCase`、`context` 和 `limit` 可选。
- `context` 最大为 10，`limit` 默认及最大值为 100。
- 每条结果包含相对路径、行号和经过控制字符清理的文本。
- 搜索不会返回 `.env*` 内容、永久禁止路径或受保护路径。

`find` 和 `grep` 可以在内部以 `shell: false` 的方式启动固定的 `rg` 可执行文件。模型只能提供被校验的搜索参数，不能控制命令名、环境或注入额外 Shell 片段。受控参数列表必须在用户可控的 pattern/path 前加入 `--` 终止选项解析。系统缺少 `rg` 时返回明确的工具错误，不降级为通用 Shell。

### `read`

按行读取 UTF-8 文本文件。

```json
{
  "path": "src/agent.ts",
  "offset": 1,
  "limit": 200
}
```

- `path` 必填。
- `offset` 从 1 开始，默认 1。
- `limit` 可选，默认及最大值为 2000 行。
- 普通文本最多返回 50KB；截断时明确返回后续读取所需的起始行。
- 第一版不读取图片、PDF 或其他二进制内容。

读取 `.env*` 时不返回原始文本，只返回：

- 变量名；
- 空值变量名；
- 重复变量及其行号；
- 无法解析的行号。

变量值、注释中的敏感内容和原始行均不能进入工具结果或会话历史。

### `edit`

精确修改一个已存在的文本文件。

```json
{
  "path": "src/agent.ts",
  "edits": [
    {
      "oldText": "旧内容",
      "newText": "新内容"
    }
  ]
}
```

- `path` 必填，目标必须是已存在的普通文本文件。
- `edits` 必须包含 1 到 20 项。
- `oldText` 必须非空、精确、唯一。
- 多项替换全部在原始内容上定位，重叠或嵌套时整体失败。
- 目标文件最大为 2MB。
- 保留 UTF-8 BOM、LF/CRLF 换行风格和文件权限。
- `.env*`、永久禁止路径和未授权的受保护路径不能使用 `edit`。
- 写入前必须显示完整的行内 unified diff 并由用户确认。

成功结果只包含路径、变更数量和首个变化行；完整 Diff 不进入模型历史，以控制上下文体积。

### `write`

创建一个新的 UTF-8 文本文件。

```json
{
  "path": "src/new-module.ts",
  "content": "export const value = 1;\n"
}
```

- `path` 和 `content` 必填。
- 目标已存在时拒绝，不能覆盖。
- 内容最大为 1MB。
- 可以在工作区内递归创建缺失的父目录。
- 所有新建目录和文件都必须再次通过工作区与保护策略检查。
- `.env*`、永久禁止路径和未授权的受保护路径不能使用 `write`。
- 新文件以整文件新增 Diff 展示，并由用户确认。

### `set_env`

安全设置工作区内 `.env*` 文件的一个变量。

```json
{
  "path": ".env",
  "key": "SERVICE_API_KEY"
}
```

- 模型参数只包含目标路径和变量名，不包含变量值。
- CLI 在本地使用隐藏输入读取变量值。
- 变量名只允许常见 dotenv 标识符格式。
- 已有变量只替换对应行；不存在时追加；保留注释、顺序、BOM 和换行风格。
- 同名变量重复或文件存在语法问题时拒绝自动修改，避免写错位置。
- 预览只显示 `KEY=<hidden>` 形式的脱敏结构 Diff。
- 用户确认后写入；工具结果只返回路径、变量名和“已设置”，不返回长度、摘要或值。
- 第一版不提供删除变量的能力。

## 组件与职责

### `WorkspacePolicy`

统一负责所有文件工具的路径解析和访问分类：

1. 相对路径以启动时解析出的 `workspaceRoot` 为基准。
2. 绝对路径只有在真实路径仍位于工作区内时才允许。
3. 对已存在路径执行 `realpath`，拒绝符号链接逃逸。
4. 对新路径逐级检查到最近存在的父目录，再验证所有待创建路径。
5. 返回 `allowed`、`protected`、`env` 或 `denied`，工具不能自行绕过策略。

读取可以跟随最终仍位于工作区内的符号链接；变更操作拒绝路径链中的符号链接，避免原子替换改变链接语义或在确认后切换目标。

### 代码工具实现

- `ls`、`read`、`edit`、`write` 和 `set_env` 使用 Node.js 文件 API。
- `find`、`grep` 使用受控的 `rg` 子进程，禁止 `shell: true`。
- 工具实现依赖 `WorkspacePolicy`，不能直接拼接工作区路径。
- 工具通过现有 `RegisteredTool` 注册；`ls`、`find`、`grep`、`read` 使用 `read` 风险等级，`edit`、`write`、`set_env` 使用 `write` 风险等级。
- 供应商适配器继续只消费工具定义和 JSON 工具结果，不感知文件系统实现。

### `ToolInteraction`

CLI 向 Conversation 注入本地交互回调，负责：

- 单次受保护路径授权；
- Diff 展示和确认；
- `.env*` 的隐藏输入；
- 暂停工具动画并恢复终端状态。

模型、模型供应商适配器、工具参数和会话历史都不能直接访问用户输入的环境变量值。

在没有交互回调或非 TTY 环境中，读取类工具仍可使用普通允许路径；所有变更、受保护路径访问和 `set_env` 默认拒绝。

## 安全策略

### 永久禁止

以下目标不提供授权入口：

- 工作区之外的路径；
- `..` 或符号链接造成的工作区逃逸；
- `.git` 目录及其内容；
- SSH 私钥、PEM 私钥以及包含私钥标记的证书文件；
- 非普通文件、设备文件、socket、FIFO；
- 包含 NUL 字节或无法作为 UTF-8 文本安全处理的二进制文件。

私钥检测在本地完成，只返回“已阻止敏感文件”，不得把文件片段放进错误信息。

### 受保护路径

以下路径默认不出现在 `ls`、`find` 或 `grep` 结果中：

- `.gitignore` 等忽略规则文件；
- 被仓库忽略规则匹配的路径；
- `node_modules`；
- `dist`、`build`、`out`、`coverage`；
- 常见 cache 和 generated 目录。

模型直接指定受保护路径时，CLI 可以请求一次性授权：

```text
Coffee 想读取受保护路径：dist/report.txt
仅允许本次操作？[y/N]
```

授权只绑定当前工具调用的规范化路径、操作类型和内容摘要，不写入配置。写操作在获得访问授权后仍要独立显示 Diff，并再次确认。

### `.env*` 特殊规则

`.env*` 规则优先于普通受保护路径：

- `read` 只返回结构诊断，不返回值；
- `edit` 和 `write` 一律拒绝；
- 只有 `set_env` 可以修改值；
- 隐藏输入、脱敏 Diff 和工具结果均不得泄露值；
- 实际值不得写入模型消息、工具调用参数、日志或 SQLite 对话历史。

这能阻止 Coffee Agent 自身意外越界或泄露秘密，但不能防御与 Coffee 同账号运行的恶意本地进程，因此不是操作系统级沙箱。

## 变更事务

`edit`、`write` 和 `set_env` 遵循同一事务边界：

1. 解析并校验参数。
2. 通过 `WorkspacePolicy` 分类路径。
3. 必要时请求一次受保护路径授权。
4. 读取原始字节并计算 SHA-256；新文件记录“不存在”状态。
5. 计算完整候选内容和 unified diff。
6. Diff 超出上限时拒绝，要求模型拆分修改。
7. 暂停咖啡动画，清理动态行，显示稳定的彩色行内 Diff。
8. 用户输入 `y` 后重新读取路径、真实路径、类型、保护状态和哈希。
9. 任一状态发生变化时返回冲突，不写入。
10. 在同目录生成临时文件，完成写入和权限设置后再执行原子替换；新文件使用排他创建保护，避免覆盖竞态。
11. 清理临时文件；如果失败发生在新文件落盘前，还要倒序删除本次创建且仍为空的父目录。
12. 返回最小化结果。

同一路径的变更通过进程内队列串行执行。失败、取消或中断都不得留下部分内容。

## 行内 TUI Diff

交互顺序如下：

```text
Coffee 准备修改 src/agent.ts

@@ -12,3 +12,3 @@
-const value = 1;
+const value = 2;

确认修改？[y/N]
```

- 红色显示删除行，绿色显示新增行，灰色显示上下文和元数据。
- 在渲染颜色前清理文件内容中的 ANSI、退格和其他终端控制字符。
- 根据终端宽度安全换行，不改变真实候选内容。
- `y` 确认；`n` 或直接回车拒绝。
- 等待输入期间不运行重绘计时器，不与 Markdown 流式输出争用终端。
- `Ctrl+C` 传播现有 `AbortSignal`，取消修改且不写入，并沿用当前 CLI 的退出行为。
- 非 TTY 环境不询问，默认拒绝变更。

Diff 最多 200 行或 50KB。超过任一限制时不隐藏剩余内容，而是拒绝整次变更，让模型拆成更小的调用。

工具活动动画增加“暂停等待确认”的内部状态。确认结束后，工具执行结果仍通过现有 success/error 活动事件收尾，避免同时存在动画和确认提示。

## 输出和历史

所有工具继续返回 JSON：

```json
{
  "ok": false,
  "code": "EDIT_CONFLICT",
  "error": "文件在确认期间发生变化，未写入。"
}
```

错误码用于让模型区分参数错误、权限拒绝、用户拒绝、内容冲突和执行失败；中文 `error` 用于解释下一步。错误信息不得包含文件秘密或 `.env*` 值。

工具调用参数与结果按现有流程进入当前会话历史，但：

- Diff 只在本地终端展示，不写入历史；
- `set_env` 参数和结果中不存在值；
- 受保护路径授权结果只返回是否允许，不保存用户按键细节；
- 被中断且未产生工具结果的回合沿用当前事务语义，不提交半个回合。

## 资源限制

| 工具 | 限制 |
| --- | --- |
| `read` | 2000 行或 50KB 输出 |
| `grep` | 100 个匹配、50KB 输出、单行 500 字符、上下文最多 10 行 |
| `find` | 1000 个路径或 50KB 输出 |
| `ls` | 500 个条目或 50KB 输出 |
| `edit` | 20 个替换项、目标文件 2MB |
| `write` | 新文件 1MB |
| Diff | 200 行或 50KB；超过即拒绝 |

`rg` 子进程达到结果、字节或取消限制后立即终止，不能先无限缓冲再截断。

## 错误处理

以下情况整体失败并保持原文件不变：

- 参数不是预期的 JSON 类型或超过限制；
- 路径不存在、越界、逃逸或命中永久禁止规则；
- 受保护路径未获得单次授权；
- `oldText` 找不到、出现多次、为空或与其他编辑重叠；
- 候选内容未产生变化；
- Diff 超出确认上限；
- 用户拒绝或中断；
- 文件在预览后发生内容、路径、类型或权限变化；
- 临时文件、排他创建、权限设置或原子替换失败。

普通工具失败返回结构化 `ok: false`，不会使整个 CLI 崩溃；`AbortError` 继续向上传播，由现有 Ctrl+C 流程处理。

## 系统提示更新

当 `workspaceRoot` 存在且代码工具已注册时，系统提示明确说明：

- 当前工作区路径；
- 可以使用哪些本地代码工具；
- 修改前优先 `read`，精确小范围编辑优先 `edit`；
- 不能声称执行了不存在的 Shell、测试或构建；
- 工具失败或用户拒绝时必须如实说明，不能假装修改成功。

工作区安全仍由 `WorkspacePolicy` 强制执行，系统提示不承担访问控制职责。

## 测试策略

### 工作区策略

- 相对路径、工作区内绝对路径和规范化路径。
- `..`、前缀碰撞、外部绝对路径和符号链接逃逸。
- 已存在文件与新文件最近存在父目录的检查。
- `.git`、私钥、二进制、设备文件的永久阻断。
- ignore、依赖、构建、cache、generated 路径的隐藏与单次授权。

### 读取与搜索

- `ls`、`find`、`grep` 的排序、限制、截断和受保护路径过滤。
- `grep` 的 literal、regex、glob、大小写和上下文。
- `rg` 缺失、退出失败、输出过大和 AbortSignal 取消。
- `read` 的 offset、limit、UTF-8 校验和截断提示。
- `.env*` 只返回变量名和诊断，任何结果中均不存在值。

### 编辑与写入

- 单项和多项精确替换。
- 零次匹配、多次匹配、重叠、嵌套和空 `oldText`。
- `newText` 为空时只删除文件内部内容。
- UTF-8 BOM、LF/CRLF 和文件权限保持。
- 新文件、父目录创建、已存在目标拒绝和大小限制。
- Diff 内容、首个变化行、控制字符清理和上限拒绝。
- 用户批准、拒绝、回车、Ctrl+C 和非 TTY。
- 预览后外部修改、符号链接切换和原子写入失败。
- 临时文件清理以及同路径变更串行化。

### `.env*`

- 隐藏输入不回显。
- 新增和更新变量时保留注释、顺序和换行。
- 重复变量和语法异常时拒绝。
- 脱敏 Diff 只显示 `<hidden>`。
- API 值不进入工具参数、工具结果、事件、日志或 SQLite 历史。

### 集成回归

- 代码工具通过现有模型中立注册表提供给不同供应商。
- 工具开始、暂停确认、成功或失败后动画和光标均恢复。
- 流式 Markdown 在 Diff 前正确结束当前片段，确认后可以继续输出。
- 现有联网、定位、计算器、登录、模型切换和历史会话测试继续通过。
- TypeScript 类型检查和完整测试套件通过。

## 验收标准

1. 在任意项目目录启动 `coffee` 后，模型可以使用六个 Pi 风格代码工具和 `set_env`。
2. 所有文件访问都由统一工作区策略限制，无法访问工作区外或永久禁止文件。
3. 每次文件内容变更都会先展示完整、经过清理的行内 Diff，并要求用户确认。
4. 拒绝、Ctrl+C、并发冲突和写入失败均不会产生部分修改。
5. `.env*` 的值永远不会进入模型上下文或持久化历史。
6. 代码工具协议与具体模型供应商无关。
7. `npm test` 与 `npm run check` 全部通过。
