# Coffee 稳定流式输出设计

## 目标

修复交互式终端中旧流式帧无法被可靠清除、导致完整回答前缀反复出现的问题，同时保留逐步显示、基础 Markdown 颜色、工具动画和安全退出能力。

## 范围

本阶段只修改 CLI 的流式显示层，不改变模型请求、SSE 解析、Agent 工具循环、会话历史或模型原始正文。

包含：

- 已完成的逻辑行只输出一次，之后不再重绘。
- 只允许当前未完成的短行进行原地刷新。
- 不安全的终端环境自动使用追加模式。
- 工具边界、完成、错误和取消路径可靠固定当前内容并恢复光标。
- 保留标题、加粗、列表、行内代码和链接等现有终端 Markdown 样式。

不包含：

- 新增 `/stream` 命令或流式设置项。
- 修改模型供应商协议或 SSE 事件格式。
- 重做工具动画。
- 引入完整 TUI 框架。

## 方案选择

采用增量行渲染，不再对当前回答的完整 Markdown 缓冲区进行周期性整段重绘。

相比继续增强整段 ANSI 重绘，该方案不会随着回答增长反复移动多行光标，也不会尝试清除已经进入终端滚动区的内容。相比完全关闭样式的原始追加，它仍能在逻辑行完成时应用现有 Markdown 格式。

## 渲染状态

`StreamingMarkdownRenderer` 保持现有公开接口：

```ts
interface StreamingMarkdownRenderer {
  showStatus(text: string): void;
  append(delta: string): void;
  finishSegment(): void;
  dispose(options?: { preserve?: boolean }): void;
}
```

内部只维护当前片段所需的有限状态：

- 尚未固定的当前逻辑行原文。
- 当前行是否已有实时预览。
- 当前片段是否已经输出内容。
- 当前终端是否允许单行刷新。
- 光标是否被隐藏。
- 非 TTY 控制序列清洗器状态。

不再保存用于显示的完整回答缓冲区，也不再记录整段回答占用的视觉行数。

## 数据流

### 收到文本增量

1. 清洗危险终端控制字符，同时保留普通换行。
2. 将增量按换行拆分。
3. 没有结束换行的部分进入当前逻辑行。
4. 每个已结束逻辑行执行一次“固定输出”。

### 固定逻辑行

1. 如果当前行存在实时预览，先清除这一行的预览。
2. 使用现有 `renderMarkdown()` 渲染完整逻辑行。
3. 写入 `Coffee> ` 或等宽续行缩进、渲染结果和换行。
4. 清空当前行状态；此后永不返回修改这行。

只有当前片段的首行显示 `Coffee> `，后续非空行使用与前缀等宽的缩进，空行保持空白。

### 当前行预览

在支持 ANSI 单行控制、终端宽度有效，并且当前行确定只占一个视觉行时，可以刷新当前行预览。刷新范围只能是当前物理行，不允许向上移动多行光标。

每次预览前动态读取 `output.columns`，不缓存创建渲染器时的宽度。

当当前行接近终端宽度时，在它仍只占一个物理行时清除最后一帧预览，将当前原文无样式写入一次，然后让该逻辑行后续 delta 直接追加。禁止等到自动换行后再尝试回退，也禁止向上移动多行光标。

### 安全追加模式

以下任一条件成立时，不使用光标移动或清行指令：

- 输入或输出不是 TTY。
- `TERM=dumb`。
- 终端宽度缺失、非有限数字或小于 1。
- 当前行可能产生自动换行。

安全追加模式为当前片段输出一次前缀，之后只追加经过清洗的可见文本，不重绘历史内容。为了确保不会重复，稳定性优先于完整的即时 Markdown 着色。由单行预览切换到安全追加时，必须先清除预览，再把尚未固定的当前原文写入一次，不能同时保留预览和原文。

## 状态与工具边界

`showStatus()` 仍只在正文出现前展示临时状态。正文开始后忽略迟到状态。

收到 `segment_end`、`tool_activity` 或 `done` 时调用 `finishSegment()`：

- 固定尚未结束的当前行。
- 当前片段有正文时只补一个结束换行。
- 清空片段状态。
- 恢复光标。

工具动画只在文本片段完全固定后开始，下一轮模型正文作为新片段输出，不跨越工具输出重绘。

## 错误、取消与清理

- 模型流中途报错时，已固定内容保持不变；当前可见行最多保留一次。
- Ctrl+C 时固定用户已经看到的当前内容，恢复光标，然后由现有中止流程退出。
- `dispose({ preserve: true })` 保留当前可见内容一次。
- 默认 `dispose()` 只清除尚未固定的临时状态或预览，不删除已固定正文。
- 所有路径都必须幂等恢复光标。
- 显示层不得修改传给 SQLite 的模型原始正文。

## 终端安全

- 继续过滤 C0、C1、CSI、OSC 和控制字符串。
- 继续将回车规范化为安全换行，避免模型覆盖历史终端内容。
- 终端宽度使用 `string-width` 计算去除 ANSI 后的中文、Emoji 和组合字符宽度。
- 模型内容不得直接注入 Coffee 自己的光标控制序列。

## 测试

### 单元测试

- 多个 delta 合并后，完成行只出现一次。
- 多行 Markdown 不会重新输出已经固定的行。
- 当前短行只使用单行清除，不产生向上移动多行的 ANSI 指令。
- 超长单行触发安全追加，不产生重复内容。
- 中文、Emoji、ANSI 样式和续行缩进宽度正确。
- `output.columns` 改变后使用新宽度。
- 非 TTY、`TERM=dumb` 和无效宽度不输出光标控制序列。
- 状态、完成、错误、取消和重复 dispose 均恢复光标。

### CLI 回归测试

- 模拟截图中的多个增长帧，最终每段正文只出现一次。
- 工具调用前固定正文，工具结束后新片段正常开始。
- Ctrl+C 和流式解析错误保留部分正文且不产生 ANSI 残留。
- 非 TTY 输出仍按 delta 顺序输出原始 Markdown。
- SQLite 中保存的正文与模型最终正文一致，不包含显示层前缀或重复帧。

## 验收标准

- 真实终端中长回答不再出现完整前缀重复。
- 已完成的逻辑行不会被后续增量重写。
- 自动换行、终端缩放和不支持 ANSI 的环境不会造成成段复制。
- 工具动画、Ctrl+C、错误输出和非 TTY 行为保持可用。
- 全部现有测试、流式回归测试和 `npm run check` 通过。
